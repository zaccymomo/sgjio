# SGJio: briefing for Claude Code

SGJio is an IS4301 team project: a **web app** (not a mobile app) that helps international residents in Singapore learn cultural norms (Singlish, hawker and workplace etiquette, and so on) and build an evidenced record of their integration effort. It is positioned alongside the government's PR journey, but **must never claim or imply that anything in the app improves PR approval chances**; ICA decides outcomes independently.

- **Backlog:** Jira project `SCRUM` on `is4301sgjio.atlassian.net`. Stories use "As a / I want / So that" with numbered GIVEN/WHEN/THEN acceptance criteria and MoSCoW priority. Refer to criteria as e.g. "SCRUM-62 AC5".
- **Design:** Figma file `SGJIO` (file key `rshLkESAaKlry48qBcYOLO`). Key frames: `home-screen` (node 30:8) and `topic-screen / Singlish` (63:5). Frames are drawn at 375px phone width; the app must also work on desktop.
- **Modules:** 1 lessons and quizzes (+ portfolio landing page), 2 buddy matching, 3 integration portfolio / tiers, 4 AI scenario chatbot. Sprint 1 covers accounts and the first lesson/admin stories.

## Repository layout

Branch `arch/microservices`: the back end is four FastAPI services behind an nginx gateway, talking through RabbitMQ (`docs/architecture/`: build plan, ADRs in `decisions/`, `diagrams.md`). `main` still has the monolith (`api/`); it is deleted here.

| Path                     | What                                                                                                                                                       |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `web/`                   | Main app, React 19 + TS + Vite, port 5173                                                                                                                  |
| `admin/`                 | Admin portal for content administrators, port 5174                                                                                                         |
| `packages/ui/`           | Shared tokens (`src/theme.css`), components, `apiFetch`, `AuthProvider`/`RequireAuth`/`useAuth`; `@sgjio/ui/lesson` is the lesson deck both front ends use |
| `services/gateway/`      | nginx on :8000, the only way in: routes `/api/*` by path, forward auth to Identity (`templates/gateway.conf.template` is the routing table)                |

| `services/learning/`     | Lesson runs, completions, progress, search, review, aptitude test and exemptions, insights; read models of content and learners (:8003)                    |
| `services/notification/` | Email worker (no HTTP); inbox `processed_events`                                                                                                           |
| `contracts/`             | Event JSON Schemas (`events/`), `validate.py`, and the auth and error contracts (`README.md`)                                                              |

| `content/`               | Lesson files the seed loads (`README.md` explains the format, `STYLE.md` the look)                                                                         |

Both Vite servers proxy `/api` to the gateway, so there is one origin and no CORS.

## Commands

Python is 3.11 via **uv** with a `.venv` per folder (`services/<name>`, `e2e`, `contracts`, `templates/platform`); never conda. If `node` isn't on PATH, run `eval "$(fnm env)"`.

```bash
./dev.local [--seed]                                   # stack up (build, wait), optional seed, both Vite servers
docker compose up -d --build --wait                    # project sgjio-ms: 4 Postgres, RabbitMQ, Mailpit, services, gateway
scripts/seed-all.sh [--demo]                           # identity, content, then learning once its read models caught up
docker compose exec <svc> python -m app.cli <command>  # identity: seed | create-admin | send-reset | seed-demo-learners | republish-learners
                                                       # content: seed | import-lessons | prune-media | republish-catalog
                                                       # learning: seed | wait-for-read-models | demo-activity | reset-read-models
cd services/<svc> && uv venv -p 3.11 .venv && uv pip install -p .venv/bin/python -r requirements-dev.txt
.venv/bin/python -m pytest                             # <svc>_test DB; identity 209, content 373, learning 258, notification 33
.venv/bin/python -m ruff check . && .venv/bin/python -m ruff format .
.venv/bin/python -m alembic revision --autogenerate -m "..."   # then READ the generated file
.venv/bin/python -m alembic upgrade head && .venv/bin/python -m alembic check
scripts/e2e.sh [--resilience]                          # 44 e2e tests through :8000 (4 resilience drills opt-in)
contracts/.venv/bin/python contracts/validate.py       # event schemas and examples
services/gateway/tests/run.sh                          # gateway routes against stub services
npm run dev:web | dev:admin                            # from repo root
npm run lint && npm run format && npm run typecheck && npm run build
```

Ports: gateway 8000; Swagger identity 8001, content 8002, learning 8003; RabbitMQ UI 15672 (`sgjio`/`sgjio`); Mailpit 8025; Postgres identity 5433, content 5434, learning 5435, notification 5436 (user = password = db name).

Seed logins: main app `newcomer@sgjio.example.com` / `UserPass123` (also `starter@`, `mixed@`, `advanced@`, `skipped@`); admin `admin@sgjio.example.com` / `AdminPass123`.

## Conventions

- Branch `SCRUM-<n>-short-name`; commit messages start `SCRUM-<n>: ...`; PRs into `main` need green CI (`.github/workflows/ci.yml`: a job per service, platform template, contracts, gateway, front end, e2e).
- Before finishing any change, run the relevant service's tests, lint and format, `alembic check`, and the front-end lint, format and typecheck; `scripts/e2e.sh` when a flow crosses services.
- **Service rules:** no service reads another's tables, and ids from other services are plain UUIDs (no FKs). Services never import each other's code. State changes go out as events written to the producer's `outbox` in the same transaction (`emit(...)`); consumers are idempotent (version guard, insert-if-absent, tombstones; Notification's inbox). A change to an event starts in `contracts/events/`. `app/platform/` must stay identical to `templates/platform/` (CI checks).
- The front ends must not change behaviour: paths, cookies, status codes and error bodies stay the monolith's, except the declared changes in `docs/decisions.md`.
- Never edit a migration already on `main`; add a new one in the owning service. Enums are stored as VARCHAR + CHECK (`_enum()` in `models.py`), not native Postgres enums.
- New settings go in the service's `app/config.py`, its environment in `docker-compose.yml`, and its `.env.example` if it has one. Never commit `.env`.
- UI: use the Tailwind tokens (`bg-brand`, `text-ink`, `text-muted`, `text-subtle`, `border-line`, `bg-surface`, `text-danger`, `rounded-sm/md/lg`, `text-2xs`, `text-caption`) and reuse `@sgjio/ui` components (`Button`, `TextField`, `PasswordField`, `Alert`, `AuthCard`, `AppShell`, `AdminLayout`, `SignInForm`, `ErrorState`, `Placeholder`). Brand red `#F43F5E` is for highlights; errors use `danger` `#DC2626`.
- Tabs whose module isn't built yet (Practice, Buddies, Portfolio) use `ComingSoonPage` in `web/`: a learner-facing summary and what the tab will do. Unfinished parts of built pages show `<Placeholder story="SCRUM-xx">`. Replace either when building that story.
- Write user-facing copy in plain language; say "select", not "tap" (web app).

## Auth (Identity, `services/identity/app/auth/`; gateway forward auth)

- One `users` table with `role` (`user`/`admin`); **separate sessions per front end** (`AuthScope.APP` vs `ADMIN`), separate cookies (`sgjio_session` path `/api`, `sgjio_admin_session` path `/api/admin`). An app session never opens admin routes. Sessions are stored hashed in Identity's `auth_sessions` and slide forward while used.
- **Gateway:** for every protected Content or Learning route, nginx calls Identity's `GET /internal/auth/app` or `/internal/auth/admin` (scope from the path, no body, no cache). On 200 Identity returns `X-User-Id`, `X-User-Scope`, `X-User-Role`, `X-User-Type` (empty for admins) and `X-Profile-Completed` plus the refreshed cookie; nginx replaces any client copies of those headers, adds `X-Gateway-Key`, and relays the cookie. No cookie for the scope: 401 at once without asking Identity. Identity down or over 2 s: 503 `service_unavailable`. Sign-out and deletion take effect on the next request.
- Protect routes: Identity's own with `Depends(require_user)` / `Depends(require_admin)` (`auth/deps.py`; the gateway passes Identity's routes through); Content and Learning with `Depends(require_principal("app" | "admin"))` (`app/platform/principal.py`), which refuses a request without the right `X-Gateway-Key`, plus an `auth_request` location in the gateway. Protect pages by nesting under `<Route element={<RequireAuth />}>`.
- Errors are `{"detail": {"code", "message", ...}}`; the front end reads them via `ApiError`.
- Sign-in never reveals whether an email exists or is an admin. Lockout: 5 consecutive failures per email per scope blocks for 15 minutes (429 with `blocked_until`; `auth/lockout.py`).
- Password rules: `password_rule_failures()` in `services/identity/app/security.py` (8+ chars, a letter and a number).
- Administrators (SCRUM-81, `services/identity/app/admins.py`): invited from the portal's Administrators page with a 3-day set-password link (`/set-password`), all with the same access. Removing one closes the account (`users.removed_at`), never deletes it; `User.is_admin` is false for removed ones, and every change is logged in `admin_events`. `create-admin` is only for the first administrator and recovery.
- Sign in with Google (SCRUM-92, `auth/google.py`): Firebase opens Google's window in `web/` (`web/src/lib/google.ts`, hidden without `VITE_FIREBASE_*`), and `POST /api/auth/google` checks the ID token (`FIREBASE_PROJECT_ID`) and starts an ordinary app session. It links a learner account with the same verified email automatically; admin and removed accounts are never reached. Someone new gets `needs_signup` and the same token is sent again with name, user type and consent. Google-only accounts have `password_hash` NULL (`User.has_password`): forgot-password emails them how they sign in, change-password refuses, and deleting is confirmed with a fresh Google token. Tests replace `google._decode_token`.
- Password reset: `request_password_reset`, `check_reset_token`, `consume_reset_token`, `set_new_password` in `auth/reset.py`. Links last **15 minutes on this branch** (5 on `main`; the email is now sent asynchronously, see `docs/decisions.md`), work once, a new request cancels old ones. Identity writes `identity.password_reset.requested` (or `identity.admin.invitation_issued`) and Notification sends the email. Endpoints `forgot-password`, `reset-password/check` and `reset-password` exist on both `/api/auth` and `/api/admin/auth`; both front ends use `ForgotPasswordCard`/`ResetPasswordCard` from `@sgjio/ui`.
- Deleting an account (`POST /api/auth/delete-account`) deletes the user in Identity and emits `identity.user.deleted` in the same transaction; Learning erases their progress and quiz and tombstones the id (`erased_learners`), Content tombstones the id (`erased_users`) and nulls it on reports, versions and media, within seconds (`app/erasure.py` in each).

## Product rules that stories depend on

- **Home page = portfolio (SCRUM-43):** one progress circle per topic with ≥1 published lesson the user can see (at their level, or completed: see Levels below), filled by _lessons completed / lessons available_ ("8 / 12"), empty "Not started", visibly distinct when complete; plus one overall figure; selecting a circle opens the topic's lesson list (SCRUM-53, built: `/topics/:id` in `web/`, `GET /api/topics/{id}` in Learning's `app/progress.py`, same counting rules as the circles). Each lesson there shows "Last attempted on <date>" and its best score, or "Not attempted yet" (SCRUM-54, which replaced the cancelled quiz history, SCRUM-42). A suggested next lesson from the weakest topic (SCRUM-6). **No daily streaks, no weekly lessons, no separate score, no leaderboard.** Keep the home screen minimal (the Integration Hub was removed).
- **Progress rules live in SCRUM-16:** finishing a lesson completes it whether its answers were right or wrong; correctness is stored separately and the best result is kept; only currently published lessons count, so completed can never exceed available. Circles show completion; correctness feeds tiers (SCRUM-27). The best score is `best_correct` of `best_scored` on `lesson_completions`; each run through a deck is a `lesson_attempts` row with its `attempt_answers` (`services/learning/app/learning.py`).
- **Lessons are decks of cards (SCRUM-19).** A card has Markdown text (bold, italics, lists, and at most one `{{blank}}`), an optional image and/or audio, and an optional question: 1 to 4 options, exactly one correct, an explanation, optional "why not" notes on wrong options, shuffled unless the author says not. A one-option question is a tap that fills the blank and isn't scored. A lesson needs at least one question to publish, belongs to exactly one topic, and should read in under 2 minutes. The document's rules live in `services/content/app/lesson_doc.py` (issues: blockers vs warnings); the shared types in `packages/ui/src/lesson/types.ts`.
- **Drafts and versions (SCRUM-52).** Editors always change a lesson's draft; publishing copies it into a numbered `lesson_versions` row, which is what users see. Statuses Draft / Published / Withdrawn; withdrawn lessons, and every version, are kept for users' history. Topic and position are not versioned. Publishing (`services/content/app/lessons.py`) sends `content.lesson_version.published` then `content.lesson.changed`; learners see it once Learning's read models have it, usually within a second.
- **Learners see the newest version** when they start or retake a lesson. Built in SCRUM-15/16 (`/lessons/:id` in `web/`): a lesson is complete when its deck is finished; the score is first-try correct answers out of the scored questions; the best percentage is kept, and a tie keeps the most recent; "mastered" means all correct. Answers are checked on the server, and the learner's copy of a lesson never contains which option is right.
- **Levels and exemptions (Epic 6, SCRUM-110, SCRUM-113).** Lessons and aptitude questions share Level 1 to 5. A question's is set at creation and never changed; a lesson's must be chosen before it is first saved and is fixed from its first publish (SCRUM-103, `level_locked` in Content; descriptions in `admin/src/lib/levels.ts`). Users have **no level of their own**: the aptitude quiz assesses each topic separately and is taken once, giving one `topic_exemptions` row per topic (level 0 to 5, 0 = nothing exempted). Every published lesson in a topic at or below that level is exempted for the user; this is worked out, never stored (`is_exempted`, `exempted_lessons`, `exemption_levels` in `services/learning/app/exemptions.py`). A user has at most one `aptitude_attempts` row (the completed quiz, with a copy of each question in `results`); exemptions can only exist beside it and are saved with it. No attempt after profile setup means the quiz was skipped (SCRUM-98), and nothing is exempted (`quiz_attempt`/`has_taken_quiz` in `services/learning/app/aptitude.py`). Lessons are not hidden by level: every user sees every published lesson (`services/learning/app/progress.py`). Exempted lessons count as completed in the circles, overall figure and topic page (each once, available unchanged), and topic pages list every lesson lowest level first with uncompleted exempted ones labelled "Exempted" (SCRUM-104, Learning's `app/progress.py`); they still open like any other. Exemptions never count in the passport, tiers or export. Skipping exempted lessons in the suggestion is SCRUM-106. The question bank is Content's `aptitude_questions` (authoring and readiness, `services/content/app/aptitude.py`), copied to Learning's `quiz_questions`/`quiz_bank` read models; a topic that ever had a question can't be deleted (`topics.assessed_at`). Results (SCRUM-100): `/aptitude/results` shows how many lessons each topic exempted (`result_out` in Learning's `app/aptitude.py`) and a radar (`TopicRadar` in `web/`); the **Profile tab** (`/profile`, which replaced the Settings tab: name, chart, profile details; Settings, opened from its gear, keeps the account, introduction, security and sign-out) draws the level reached per topic (`level_reached` in Learning's `app/progress.py`, also on `/api/progress`). Learners see the quiz called the "aptitude test". Exempted lessons show in a lighter red (`brand-light`) and with a dashed mark (`LessonMark`).
- **Introduction (SCRUM-94).** While `users.intro_finished_at` is empty, `RequireIntro` in `web/` sends every signed-in page to `/intro` (`IntroPage`: Newcomer or Singaporean screens, Skip, "2 of 5"). Finishing or skipping calls `POST /api/intro/finished` (Identity's `routers/onboarding.py`), which returns the user for `setUser` from `useAuth`, then goes to profile setup. `/intro?replay=1` (from Settings) records nothing. Seed and demo users have already seen it; register a new account to see it.
- **Search (SCRUM-85).** The landing page's search bar drops down matching lessons as the user types (`LessonSearch` in `web/`, `GET /api/search`, `search_lessons` in Learning's `app/progress.py`, from `lesson_decks.cards_plain_text`): title and card text of the latest published version only. A lesson opened from it steps back to the results (`state={{ from: "search" }}`, as topic pages pass `"topic"`).
- **Reported problems (SCRUM-82, SCRUM-83).** Learners flag a card from the flag in the lesson's top bar (`cardActions` on `LessonDeck`); `lesson_reports` keeps the lesson, version, card id, reason and note. Admins see them at `/reports` in `admin/`, never with the reporter, and mark them Fixed or Dismissed (kept). Rules in `services/content/app/reports.py`.
- **Media** (images, audio) is uploaded once, stored in Content's Postgres (`media_assets`, `services/content/app/media.py`) and served publicly at `/api/media/{id}`; lessons refer to it by id. Images become WebP at most 1600px wide.
- Open decisions and the defaults chosen are in `docs/decisions.md`. Don't change them silently; flag it.
